Bridge 0.11.1 makes direct sites work for every subdomain and fixes a DNS leak in 0.11.0.

**Download `Bridge-0.11.1.dmg`** below. `Bridge.zip` is for the built-in updater of earlier versions.

## Install

Bridge is free and not notarized by Apple, so macOS warns the first time. The disk image has an installer script that copies Bridge into Applications and removes the quarantine flag:

1. Open `Bridge-0.11.1.dmg`.
2. In Terminal, run:
   ```bash
   bash "/Volumes/Bridge 0.11.1/Install Bridge.command"
   ```
3. Click the **VPN** icon in the menu bar → **Install Network Helper…** (one password prompt).

Updating: use **Update to Bridge 0.11.1…** in the menu, then **update the helper** when asked: the fixes are in the helper.

## What's new

- **Subdomains go direct too.** DNS for direct sites now goes to a small DNS proxy in the helper (127.0.0.1:53535). It asks your network's DNS directly through Wi-Fi or Ethernet and routes every address it hands out around the VPN before the app gets the answer. With `kinopoisk.ru` in the list, `api.ott.kinopoisk.ru`, `graphql.kinopoisk.ru` and any other subdomain now go direct, not just the domain and `www.`.
- **DNS leak fixed.** In 0.11.0, when your Wi-Fi used a public DNS server (e.g. 1.1.1.1) that the tunnel also used, the route Bridge added to reach it sent the tunnel's own DNS queries outside the VPN. The proxy now reaches the network's DNS by binding to the interface, without routes.
- **No more extra search domains.** Domains in the list were added to the system's search domains; they no longer are.
- **IPv4 only where IPv6 can't go direct.** If the tunnel or the network has no IPv6, the proxy answers direct sites with IPv4 addresses only, so apps don't try IPv6 through the VPN.
- Sites often load from other domains as well (a site on `kinopoisk.ru` also uses `yandex.net` and `yastatic.net`): add those to the list too.

## Bridge 0.11.1 — по-русски

**Скачайте `Bridge-0.11.1.dmg`** ниже (`Bridge.zip` нужен встроенному обновлению старых версий).

**Установка.** Откройте DMG и выполните в Терминале:

```bash
bash "/Volumes/Bridge 0.11.1/Install Bridge.command"
```

Затем значок **VPN** в строке меню → **Установить сетевой помощник…**. При обновлении обязательно обновите помощник, когда Bridge предложит: исправления находятся в нём.

**Что нового:**
- **Поддомены тоже идут напрямую.** DNS для сайтов напрямую теперь идёт через небольшой DNS-прокси в помощнике (127.0.0.1:53535). Он спрашивает DNS вашей сети напрямую через Wi-Fi или Ethernet и направляет в обход VPN каждый адрес из ответа ещё до того, как ответ получит программа. Если в списке `kinopoisk.ru`, напрямую идут `api.ott.kinopoisk.ru`, `graphql.kinopoisk.ru` и любые другие поддомены, а не только домен и `www.`.
- **Исправлена утечка DNS.** В 0.11.0, если в Wi-Fi был указан публичный DNS (например, 1.1.1.1), которым пользовался и туннель, маршрут к нему уводил DNS-запросы самого туннеля мимо VPN. Теперь прокси ходит в DNS сети через привязку к интерфейсу, без маршрутов.
- **Домены из списка больше не попадают в search domains системы.**
- **Только IPv4, где IPv6 не может идти напрямую.** Если у туннеля или сети нет IPv6, прокси отдаёт для сайтов напрямую только IPv4-адреса, и программы не пытаются идти по IPv6 через VPN.
- Сайты часто подгружают данные с других доменов (Кинопоиск — ещё с `yandex.net` и `yastatic.net`): добавьте и их.
